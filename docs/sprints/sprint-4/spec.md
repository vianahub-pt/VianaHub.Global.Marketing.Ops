# Sprint 4 — Scheduling + Observability + Operational Hardening (REVISED)

## Goals

1. **Cron Scheduler** with explicit timezone semantics, configuration validation, deterministic behavior suitable for testing, and prevention of incompatible overlapping executions.
2. **Batch Processing** with controlled bounded batches, deterministic item handling, per-item outcome isolation, preservation of existing idempotency guarantees, and defined behavior for partial failure.
3. **Observability** with structured operational events/metrics, run/schedule/batch correlation, no secrets or sensitive payload leakage, and local/default implementation behind appropriate contracts.
4. **Audit Logging** with durable operational audit trail, relevant lifecycle events, timestamps and correlation identifiers, redaction requirements, and explicit distinction between audit history and mutable run state.
5. **Alerting** with decoupled/testable alert contract, local/default implementation for MVP, severity and deduplication policy, and no requirement for an external SaaS notification provider.
6. **Automated Recovery** that automates recovery only where existing retry policy permits, preserves **`waiting_manual`** and non-retryable semantics, never bypasses CAPTCHA/MFA/authorization/verification/human-required states, and is restart-safe.
7. **Operational Hardening** with read-only orphan lock detection/diagnostics, actionable manual-recovery guidance in operational errors and runbook, synchronous busy-wait removal (without weakening exclusive fail-closed locking), graceful shutdown/restart behavior, and actionable operational errors.

## Architecture Constraints

1. **Preserve existing contracts:** **`RunRecord`**, **`RunRepository`**, **`Checkpoint`**, **`PlatformAdapter`**, **`AdapterContext`**, **`transitionRunState`** must not be changed in a way that breaks existing contracts.
2. **No new runtime dependencies:** The only runtime dependency is **`Zod`**. Scheduling and batch must be implemented with native **`node:timers`**/**`node:crypto`**.
3. **Deterministic testing:** All components with temporal behavior must accept clock injection (**`Clock`** interface pattern).
4. **Filesystem-first:** Persistence for schedule, batch, audit, alert follows the same pattern as **`FileRunRepository`**.
5. **Pilot scope preserved:** Scheduling and batch respect **`checkPilotScope`** and **`checkLivePilotGate`**.
6. **Idempotency preserved:** Existing idempotency keys cannot be weakened. Batch items must have independent idempotency.
7. **Redaction preserved:** **`redactError`**/**`redactLog`** continue to be applied to all operational outputs.
8. **Zero new npm runtime dependencies** -- no supply-chain risk.
9. **Fail-closed lock invariant preserved:** An existing lock means ownership is not safely known. Ambiguous ownership must fail closed. Automatic recovery must NOT delete or rename canonical lock paths. Lock remediation requires explicit operator action.
